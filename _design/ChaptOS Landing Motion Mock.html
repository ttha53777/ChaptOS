01  /  THE PROBLEM

Most chapters run on four tabs and one person's memory.

A sheet for dues. A group chat for attendance. A doc nobody opens. And a president who is the only one who knows what's actually true — right up until they graduate.

What changes

ChaptOS is the system of record underneath all of it. One org, one roster, one ledger, one activity log that every page writes to.

When the exec board turns over in April, the chapter doesn't start from zero. The record is the handoff.

04  /  GUARANTEES

Three things it
refuses to do.

Chapter software holds money, grades, and a list of everyone's name. The interesting part isn't what it can do — it's what it won't.

Won't move money quietly

Nothing hits the ledger without an approval.

Dues payments and reimbursements are requests. A treasurer approves, and only then does the ledger row get minted and the balance move — in a single transaction, both books or neither.

Reimbursement · banner printing$84.20
Treasurer reviewPending
Ledger · expense posted−$84.20
Won't let the AI write

The assistant proposes. A human confirms.

Read tools answer. Write tools only ever return a validated proposal — never a database call. Your confirmation is what sends it through the real route, with your real permissions.

16 read tools · answer directly
6 write tools · propose only
1 confirmation · yours
Won't leak across orgs

Every org is its own tenant, down to the row.

Queries carry your org automatically, and Postgres row-level security enforces it underneath — so a bug in a query can't return another chapter's roster. One account, many orgs, no bleed.
