When are we free?

Ask “what's free in November?” today and you get a list of what's on — then you do the subtraction yourself. Availability answers draw the gaps. One new shape, availability, in three modes plus an honest variant: the model names the window and what it needs; the server decides which days are open from the calendar tools it already ran, and ranks the picks in code. It never claims to know anyone's personal schedule.

01

Open dates

“When are we free for…?” is answered on a month page, not a list. Clear days are washed mint, the days you can't use are already full of ink, and the pick that fits what was asked gets bracketed. Then the picks ranked, each with its reasons.

Fires when

The question asks for free dates: “when are we free”, “what's open”, “any free weekends”, “a good date for…”. The window caps at ~6 weeks; longer stays as rows.

Payload

shape: { type: "availability",
  mode: "open",
  start: "2026-11-04", end: "2026-11-30",
  need: { span: 2, days: ["sat","sun"] } }
// server fills:
days:  [{ date, items: [{ ref, title, time,
          cat, mandatory }], open }]
marks: [{ date, kind: "holiday" | "term_end" }]
picks: [{ start, end, pros[], cons[] }]

Fed by

list_calendar_eventslist_deadlineslist_partieslist_service_events
Open = no event on that date. Deadlines are drawn but don't block a day: a due date isn't a booking. Picks are ranked in code: a clean span beats a partial one; a holiday, or an event the night before or after, is a con. The model writes need and the verdict, never which days are open.
Holidays come from a fixed table (US federal + Thanksgiving week) and the term end from the Semester row. Both are soft marks; neither makes a day busy.

Busy dates

“What's busy?” as a load strip: one column per day, one block per event, mandatory ones filled and hatched. Busy days get inked labels, back-to-back stretches get a bracket, and the open days are named at the bottom so you don't have to count blank columns.

Fires when

The question asks what's taken: “busy”, “packed”, “what's on”, “slammed” over 8–21 days. Seven days or fewer goes to the existing Week shape, which already does this better.

Payload

shape: { type: "availability",
  mode: "busy",
  start: "2026-11-05", end: "2026-11-18" }
// server fills days[] (as in open) +
busy:    [date]       // mandatory, or 2+ events
crunch:  [{ from, to, gapHours: 11 }]
rows: busy days, mandatory first

Fed by

list_calendar_eventslist_deadlines
Busy is a rule in code (any mandatory event, or two or more), shown the same way every time. Events only store a start time, so a crunch is measured start to start (under 14h, across two days) and labelled that way. No block pretends to know how long anything runs.

Fires when

One named date is asked about: “is the 13th free”, “can we do Saturday”, “anything on Nov 21?”. Open gets an Open stamp in mint and the same ticket.

Payload

shape: { type: "availability",
  mode: "day",
  date: "2026-11-13",
  near: { days: ["fri","sat"], within: 9 } }
// server fills:
day:   { open, items[], after: items[] }
nearby:[{ date, offset, pros[], cons[] }]

Fed by

list_calendar_eventslist_partiespropose_add_calendar_event
Bare days resolve the way day_of_month already does: pinned to the month in context, and shown in the ledger (“Fri Nov 13”) so a wrong guess is visible. Tapping a nearby night opens the existing propose_add_calendar_event writ, with its permission gate. Nothing is written until Approve.

Everyone free?

“When is everyone free?” is the question Ask Chapt can't fully answer, and the reply says so before anything else. It shows the evenings the chapter calendar leaves clear, names what it can't see, and offers the one move that gets the real answer: asking everyone.

Fires when

The question is about people's time: “everyone”, “most of us”, “when can exec meet”. Any people-free question goes to 01–03.

Payload

shape: { type: "availability",
  mode: "open", grain: "evening",
  start: "2026-11-09", end: "2026-11-15",
  people: true }        // → blind panel
// server fills pins[] at start time,
// clear[] evenings; poll options =
// clear evenings, model picks the times

Fed by

list_calendar_eventslist_pollspropose_create_poll · new
people: true makes the blind panel compulsory; the model can't drop it. Events are drawn as pins at their start time, never as blocks, because the data has no end time. The poll writ is new: it mirrors propose_add_calendar_event, gated on whoever can create polls, and its options can only be clear evenings from this answer.
