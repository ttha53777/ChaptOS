What do I have this week?

The current week shape draws seven equal columns, so the asker reads the whole calendar to find out what's next. This version answers in the order people actually want it: the outline of the week in one strip, a ticket for what's next, then the days as a ruled agenda with free days called out. Same data, same rows, a few additive fields.

Fires when

Same trigger as today's week shape: “what do I have this week”, “what's on this week”, “my week”, “next week”. Nothing new for the model to learn.

Payload

shape: { type: "week", start, items }
// additive on WeekItem:
place:     string | null
mandatory: boolean
mine:      "assigned" | "owner" | null
attended:  boolean | null  // past only
// additive on WeekShape:
next:  index into items | null
after: WeekItem | null   // first thing
                         // past the week

Fed by

list_calendar_eventslist_deadlinesweekly_digest
The ticket is picked in code: the first item at or after now. The countdown is drawn on the client from the item's date and time, so it never goes stale in a saved conversation. A deadline with no time can't be “next” while a timed event is still ahead that day.
Events have no end time, so nothing here is drawn as a duration. Strip chips are start times only. Free means no event that day: a due date doesn't block a day.
“You were there” reads the asker's own attendance row, and only for days already past. No row, no pill.

Rule

With one item left in the week the agenda isn't drawn. The single row still ships in rows, bound to the ticket.
After this week is one extra read: the first event or deadline after the seventh day, same scope as the week itself. It is never counted in the verdict or the tally.
